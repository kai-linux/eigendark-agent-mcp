# Security controls and prevention map

Security fixes are incomplete until the violated invariant is enforced by an
automated regression gate. This map records the originating design failure, why
the previous pipeline missed it, and the permanent control.

| Invariant | Original cause | Why prior CI missed it | Permanent prevention |
|---|---|---|---|
| MCP protocol behavior comes from the official SDK. | A hand-written JSON-RPC loop implemented obsolete framing and partial lifecycle behavior. | Tests asserted the same custom framing instead of using an independent client. | Official MCP client integration test, newline subprocess smoke test, and bounded transport tests on Python 3.11 through 3.14. |
| Tool inputs match exact schemas. | Schemas were advertised but not enforced, and action arguments were unconstrained. | Happy-path tests called handlers directly and never submitted adversarial values. | Draft 2020-12 validation before every handler plus valid/invalid tests for every action family. |
| Credentials never cross the model boundary. | Credential-delivery tools and credential arguments made bearer values model-visible by design. | Tests explicitly expected raw credentials to be returned. | Credential-name schema scan, output redaction tests, bounded in-memory store tests, and end-to-end secret canaries. |
| Authentication never appears in a URL. | The client used a legacy GET query although the service documents POST state reads. | Mocks checked returned data but did not assert HTTP method, URL, and body separately. | Contract test requires POST, a query-free path, and an internal body token. |
| Authentication cannot follow a redirect. | The default URL opener inherited redirect replay behavior. | No hostile redirect server or request-header assertion existed. | Redirect handler rejects every 3xx; regression tests verify refusal and `unredirected_header` use. |
| Remote content is bounded and untrusted. | Raw remote objects and text were passed to the model without structural limits or a stable trust warning. | CI had no adversarial nesting, size, control-character, or prompt-injection fixtures. | Recursive node/depth/item/string limits, trust notice on every result, DLP checks, and adversarial fixtures. |
| Errors cannot reflect credentials or internals. | Raw HTTP bodies, exception reasons, and validation strings were included in tool errors. | Error tests covered only a small set of field names. | Broad field/value redaction, generic transport/internal failures, encoded-secret tests, and official-client error canaries. |
| Every Eigendark capability family is blocked from Git history. | Secret scanning recognized API keys but had no custom patterns for matchmaking, seat, review, or spectator capabilities. | The previous custom Gitleaks rule covered only the `ed_` prefix. | Full-history Gitleaks scans cover all documented capability prefixes; only exact, named synthetic regression values are allowlisted. |
| Runtime state is bounded and isolated. | A process-global list grew without a cap and accumulated duplicate secrets. | Short tests never exercised eviction or concurrent access. | Locked LRU credential store capped at 32 matches, deduped sensitivity set, and eviction tests. |
| Hosted conversations cannot inherit or cross-read credentials. | A long-lived HTTP MCP process would otherwise share the stdio transport's process credential store across unrelated clients. | Stdio tests correctly assumed one process per agent and had no concurrent protocol sessions. | Hosted startup refuses process-wide credentials, each MCP protocol session receives a weakly held credential store, sessions expire, and isolation/cleanup tests use distinct live session objects. |
| Anonymous ChatGPT access does not make the general agent API anonymous. | Reusing the full stdio surface or publishing bearer inputs would widen authorization and invite credential exfiltration. | Existing tests enumerated only the local eleven-tool server. | The hosted server advertises exactly three no-auth, exact-schema tools; onboarding and capabilities remain internal, tool metadata mirrors no-auth security schemes, and an official protocol integration test scans the public surface. |
| Only OpenAI's hosted connector can reach the production MCP route. | A public no-auth URL could be invoked directly by arbitrary internet clients and consume sandbox or match capacity. | Application-only authentication cannot prove the calling platform. | Nginx validates the current OpenAI connector CA chain and forwards overwritten certificate evidence from a loopback proxy; Python independently checks the expected SAN, client-auth EKU, and validity while request/session/rate caps limit abuse. |
| Cancellation cannot escape the worker limit. | Blocking tool calls were abandoned on host cancellation, which releases AnyIO's capacity token while the underlying thread continues. | The suite checked ordinary concurrency and errors but did not cancel an in-flight blocking worker. | Canceled calls remain shielded until their finite-timeout worker exits; a behavioral test proves a second call cannot acquire the sole test slot early. |
| Dependency versions are supported and audited. | Python 3.9 support constrained security-tool upgrades, and dependencies were installed from open ranges. | The matrix checked import/test success only. | Python 3.11 minimum, an exact MCP SDK dependency, hash-locked runtime and development graphs, `pip-audit`, weekly scans, lock drift checks, and Dependabot. Locked CI/container installs reject source distributions. |
| Locks include interpreter-conditional transitive dependencies. | Universal lock generation inherited the resolver interpreter and omitted dependencies required only by Python 3.11. A reused local environment already contained them. | The old pipeline had no clean minimum-version hash-locked installation; local test reuse masked the incomplete lock. | Resolution is anchored to Python 3.11, and clean CI runners install the hash-locked graph on Python 3.11 through 3.14 before tests. The policy checker enforces the matrix and resolver floor. |
| Package and registry metadata describe a real artifact. | Metadata was added before the PyPI artifact existed and referenced a retired schema. | CI parsed neither the registry schema nor PyPI availability/version parity. | Current official schema validation, cross-file version script, package build/install smoke, trusted publishing, byte-for-byte PyPI digest comparison, cryptographic publisher-attestation verification, and post-release registry package verification. |
| Source archives are complete and safe to inspect. | Setuptools auto-included test modules while omitting their shared fixture and imported security scripts. | Building a wheel from the sdist exercises runtime sources but does not prove that audit and test assets are internally complete. | An explicit manifest includes tests, controls, workflows, and locks; the package gate rejects missing files, traversal paths, links, special files, unexpected artifacts, and oversized archives. |
| Releases contain only protected-branch code. | A mutable tag name was checked out independently in several jobs, without proving that its commit had passed through `main`. | Pull-request CI does not exercise release events, and the release workflow trusted repository writers to select a reviewed tag. | Every release job checks out the immutable event SHA; the build proves the tag resolves to that SHA and that the commit is in protected `main` before any OIDC publication job can run. |
| CI workflows are themselves least privilege. | Workflows lacked timeouts, concurrency controls, explicit checkout credential isolation, and workflow static analysis. | The pipeline analyzed application code only. | Read-only defaults, per-job permissions, SHA-pinned actions, `persist-credentials: false`, timeouts, concurrency, CodeQL, zizmor, and scheduled security scans. |
| Exactly one CodeQL configuration owns scanning. | GitHub default setup was already enabled when an advanced workflow was introduced, and GitHub rejects SARIF from advanced setup while default setup is active. | Repository files cannot reveal an account-level default-setup toggle, and the prior branch rules did not require CodeQL. | Default setup is disabled; the versioned advanced matrix scans Python and Actions. Both CodeQL contexts are required, so re-enabling default setup causes a blocking failure instead of silently losing analysis. |
| Security workflows remain valid YAML. | A binary-only pip option containing `:all:` was placed in an unquoted plain scalar, which YAML interpreted as mapping syntax. | Python and shell validation do not parse workflow YAML, and workflow-local gates cannot start when their own file is invalid. | A checksum-pinned actionlint pass validates every workflow; the repository policy checker also rejects YAML-sensitive install options outside block scalars, while required contexts make a missing workflow run merge-blocking. |
| Container findings cannot silently age or overmatch. | The container was only started; OS packages were not vulnerability-scanned. | A functional smoke test cannot identify vulnerable base packages, and a CVE-only suppression could hide the same identifier in another package. | SHA-pinned Trivy scan, short-lived exceptions scoped to exact Debian package/version PURLs, a policy validator, weekly rescans, and Docker Dependabot updates. |

Pull requests must keep the test and control in the same change. Disabling a gate
requires a documented risk decision, an owner, and an expiry date.
